# PPTX 文件交换（2026-09-12）

后续更新：0.2.0 默认嵌入模式不带文件/平台栏；demo 才展示。导出现在返回 filename/mime/warnings 并固定模型快照；codecRevision 为 4（删除标记）。ZIP 增加解压前目录声明配额检查，仍不等于完整恶意文件防护。最新状态以 [补充交付审计](DELIVERY-CONTRACT.md) 为准；下文为 0.1 交付时记录。

## 用户路径

顶部“上传 PPTX”可选取或拖入单个 `.pptx`，最大 30 MB。选择后显示名称与大小，点击“上传并打开”；处理期间可取消，失败保留窗口以便重试。不接受旧 `.ppt`、宏 `.pptm` 或 JSON。顶部“下载 PPTX”及文件菜单入口输出原生 OOXML；支持的文本、图形、表格与图表可继续编辑，并非整页截图。

演示宿主在服务器解析实际 PPTX，将图片与全新房间在同一 SQLite 事务中提交，再通过空 Y.Doc 接收服务端基线。新链接可刷新、重开和多人协作。原房间及 epoch 保留，不允许指定目标房间覆盖；原文稿有未确认更新时不切换、不清空 outbox。

## npm 与宿主责任

- `onImport(file, { signal })`：上传、业务权限、资源创建与路由切换均属于宿主。取消、卸载、禁用会 abort；宿主必须检查 signal 和当前文稿身份，不能应用迟到结果。原单参数回调类型兼容。
- `onExport('pptx')`：宿主获取快照、解析图片、调用 `exportPptx` 并下载。工具栏先 flush 当前 Slate 本地文本；格式转换器本身不产生 Yjs 更新、不改保存状态。
- 未注入回调时按钮禁用；只读不允许上传，是否可下载由宿主提供的回调决定。
- `/pptx` 为纯格式子路径，提供转换器、文件校验、MIME/大小常量及安全下载文件名助手。JSON 仍可作内部数据接口，但不是用户文件交换能力。
- schema 2 / protocol 1 / codecRevision 3 未变；存量文稿不迁移。仅导入的新文稿建立新 lineage / epoch。

## 防护与限制

演示接口要求有效可写 WebSocket 会话，解析后再次校验；限制压缩体积、基础包结构与解压后大小。图片重新分配资源 ID，仅保存 10 MB 内通过基础签名检查的 PNG/JPEG/GIF，其他格式（包括 SVG）跳过并报告。此检查不等于完整恶意文件扫描或解压前 ZIP 炸弹防护。

演示服务不具备生产 Doca 身份、租户隔离和 ACL，不应暴露到公网。生产宿主需要完整权限校验、文件扫描、解压配额、配额控制和资源生命周期管理。取消若晚于服务端提交，可能留下独立上传副本，但不会覆盖原文稿；演示不自动回收该副本。

导入属于 OOXML 支持子集：主题/母版继承、嵌套组合、复杂动画和特殊图表等仍可能降级。兼容性报告是 best-effort，不能保证穷尽损失。不能宣称无损往返或完全对齐 PowerPoint；PowerPoint / WPS / Keynote 桌面实测依用户决定暂缓。

## 验证证据

- 文件校验：扩展名、空文件、超限、损坏包及下载文件名；纯导出不产生文档事务。
- 上传窗口：选取文件、错误重试、进行中取消、权限撤销时 abort。
- 真实 HTTP + WebSocket：拒绝只读/无效会话与损坏文件，新房间及新 epoch，图片持久化，双客户端基线一致，编辑 ACK 与重连 checkpoint，原房间字节不变，再导出/导入。
- 浏览器通过系统选择器上传真实两页 PPTX（中文、形状、表格、图片、图表和备注），编辑标题与正文，刷新恢复，再下载实际 `.pptx` 文件。测试使用隔离房间，未改用户原 Demo。
